# Netrin Appearance v3 Development Tutorial

This tutorial starts from an empty directory and completes the pre-submission loop: source creation, live preview, static validation, deterministic packaging, and real-route review. Run commands from the Netrin repository root; they work in PowerShell and other terminals.

Use the [authoring contract reference](./APPEARANCE_AUTHORING.en.md) for complete field lists. In Codex, invoke `$author-netrin-appearance` for a guided human-AI workflow.

## 1. Environment, directories, and boundaries

Install Node.js and npm, and make Chrome, Chromium, or Edge available to the repository. Install dependencies and confirm that the CLI starts:

```powershell
npm install
npm run appearance:check -- --help
```

The second command may print usage or an input error because no source was supplied. That is expected; the important result is that the script starts.

This tutorial uses two Git-ignored directories:

```text
appearance-work/<id>/       appearance source
appearance-output/<id>/     package, report, and screenshots
```

An appearance package may change only Netrin-owned colors, typography, materials, constrained layout, and motion:

- A `skin` is a user-uploadable declarative ZIP. It never receives React, TypeScript, or script execution.
- A `phenotype` ships with application source. The built-in Field Guide is a phenotype, not an uploaded package.
- The AMap base-map style remains an independent user setting. A skin may style only Netrin controls and map overlays.
- A skin cannot change routes, business logic, data, accounts, submission, or moderation behavior.

Choose a lowercase hyphenated ID such as `song-mountain-map`. It must match `^[a-z0-9]+(?:-[a-z0-9]+)*$`.

## 2. Create the source and start the live workbench

Create a project:

```powershell
npm run appearance:init -- song-mountain-map appearance-work/song-mountain-map
```

The initializer refuses to overwrite a non-empty directory and creates:

```text
appearance.manifest.json
tokens.json
theme.css
README.md
assets/
```

`README.md` is source-author documentation and is not included in the final archive. Start live development:

```powershell
npm run appearance:dev -- appearance-work/song-mountain-map
```

Keep that terminal running. Open the local address printed by Vite, then navigate to `appearance-studio?tab=workbench`. The development server reads only the selected source directory. It keeps the candidate in memory, does not install it or write IndexedDB, and does not contact Supabase, AMap, or external networks.

The workbench recompiles every file change and shows the Manifest, token graph, CSS diagnostics, coverage sources, and isolated preview. It uses three columns on wide desktops, two at medium widths, and one at 390×844; import, lists, preview, audit, and submission controls remain accessible at every size. The fixed 390px Shadow DOM preview scrolls inside its own narrow column instead of widening the page. Use a second terminal for the remaining commands.

## 3. Author the Manifest and three token layers

First update the author-owned fields in `appearance.manifest.json`:

```json
{
  "schemaVersion": 3,
  "packageFormat": "netrin-appearance-zip",
  "interfaceContractVersion": 2,
  "id": "song-mountain-map",
  "displayName": "Song Mountain Map",
  "summary": "A restrained field-map appearance inspired by Song landscapes.",
  "version": "0.1.0",
  "type": "skin",
  "author": "Your name",
  "license": "MIT",
  "compatibility": { "minAppVersion": "0.1.0" },
  "entrypoints": { "tokens": "tokens.json", "theme": "theme.css" },
  "assets": [],
  "files": []
}
```

Do not add `screens` or `components`. The packager rebuilds entrypoint, file, and asset hashes instead of trusting author-declared coverage.

`tokens.json` must keep three layers:

```json
{
  "primitive": {
    "color": {
      "pine-950": { "$type": "color", "$value": "#101713" },
      "paper-100": { "$type": "color", "$value": "#F2EBD8" }
    }
  },
  "semantic": {
    "surface": {
      "app": { "$type": "color", "$value": "{primitive.color.pine-950}" }
    }
  },
  "component": {
    "panel": {
      "background": { "$type": "color", "$value": "{semantic.surface.app}" }
    }
  }
}
```

Keep every required token generated by the initializer. This abbreviated example only demonstrates reference direction:

- `primitive` contains literal colors, dimensions, durations, fonts, and shadows.
- `semantic` references primitive values.
- `component` references semantic values.
- References use `{primitive.color.pine-950}` and must preserve type.
- The resolved `component.control.min-target` must be at least `44px`.

Stable outputs include `--surface-app`, `--foreground-default`, `--border-default`, `--signal-success`, `--button-bg`, `--field-border`, `--focus-ring`, and `--control-min-target`. See the [Token Schema](../appearance/appearance.tokens.schema.json) for the complete structure.

## 4. Author constrained CSS

`theme.css` may consume stable variables and declare package-ID-prefixed private variables:

```css
[data-appearance-hook="app-shell"] {
  --song-mountain-map-paper-grain: 0.035;
  background: var(--surface-app);
  color: var(--foreground-default);
}

[data-appearance-hook="button"] {
  border-radius: var(--button-radius);
  box-shadow: var(--shadow-hard);
}

[data-appearance-screen="route-detail"]
[data-appearance-hook="route-card"][data-appearance-state="active"] {
  border-color: var(--signal-success);
}

[data-appearance-hook="button"]:focus-visible {
  outline: 2px solid var(--focus-ring);
  outline-offset: var(--focus-offset);
}

@media (prefers-reduced-motion: reduce) {
  [data-appearance-hook="button"] {
    animation: none;
    transition: none;
  }
}
```

Use only stable screen, hook, state, slot, ARIA, and native-control attributes. Global and universal selectors, scripts, hidden critical controls, fixed full-screen overlays, excessive z-index, AMap-provider selectors, and motion without a reduced-motion override are forbidden.

The home brand label exposes four stable slots so the container, text, and status mark can be styled independently:

```css
[data-appearance-slot="brand-wordmark"] { background: var(--surface-paper); }
[data-appearance-slot="brand-title"],
[data-appearance-slot="brand-name"] { color: var(--signal-info); }
[data-appearance-slot="brand-mark"] { background: var(--signal-success); }
```

Do not target private application classes such as `.home__wordmark` or `.home__brand-name`.

For a request such as “xuan-paper ground, mineral-blue text, mineral-green seal, and a Song-style serif wordmark,” use `brand-wordmark` for paper, border, spacing, and shadow; `brand-title` / `brand-name` for mineral-blue text and the font stack; and `brand-mark` for the mineral-green seal. Do not say that the Logo cannot be changed, and do not edit the home component. Preserve brand text, localization semantics, accessible names, and status meaning. If any stable slot is missing from the real DOM or contract, stop editing the appearance source and report `需要先扩展应用契约` (the application contract must be extended first).

Maintain at least 4.5:1 body-text contrast, visible keyboard focus, 44×44 targets, no horizontal overflow at 390×844, and visible AMap attribution.

## 5. Add assets only when needed

Start with tokens and CSS. When an asset is genuinely necessary, place it under `assets/`:

- PNG, JPEG, WebP, and WOFF2 are allowed.
- Extension and magic bytes must agree; renaming an invalid file does not pass audit.
- SVG, HTML, JavaScript, data URLs, and remote URLs are forbidden.
- Traversal paths, symlink targets, and references outside the package are forbidden.
- A WOFF2 font needs an explicit license. Do not ask AI to download fonts from the web.
- Keep bitmap dimensions and byte size reasonable and record their source or generation method.

Consume an asset through its package-relative path, for example `background-image: url("assets/logo.webp")`. A fully graphical Logo is also restricted to a Manifest-declared package-local PNG, JPEG, or WebP; if no compliant bitmap is available, AI must request one first. Preserve accessible brand text or an equivalent accessible name. The packager records the asset in the Manifest list; after audit, the application maps it to a temporary Blob URL and revokes that URL when the appearance unmounts. Undeclared paths and all external URLs are rejected.

The packager generates Manifest file and asset hashes. Do not copy hash arrays from an old package.

## 6. Run static validation and fix diagnostics

After each substantial edit, run:

```powershell
npm run appearance:check -- appearance-work/song-mountain-map --json
```

The report marks only executed checks as `passed` or `failed`; unexecuted work remains `not-run`. Use these location fields:

| Field | Use |
| --- | --- |
| `file` | Open the failing Manifest, token, CSS, or asset file |
| `line` / `column` | Locate the JSON or CSS text |
| `selector` | Identify the rejected CSS selector |
| `tokenPath` | Locate a missing, inverted, cyclic, or mistyped reference |

Common fixes:

- Unresolved reference: correct the path and restore any required token.
- Inverted layer: keep primitives literal, semantic-to-primitive, and component-to-semantic.
- Cycle: move the shared literal down to primitive and restore one-way references.
- Wrong type: use the same `$type` at both ends of a reference.
- Low contrast: increase the luminance difference between foreground and its surface.
- Target below 44px: resolve `component.control.min-target` to at least `44px`.
- Rejected CSS: use the reported selector and location to switch to a stable hook or remove the unsafe declaration.
- Asset failure: inspect path, extension, magic bytes, size, and license.

Continue to visual confirmation only after the static report is valid and activatable.

## 7. Review the workbench matrix

The workbench exposes ten real screen families:

`map-navigation`, `route-catalog`, `route-detail`, `route-authoring`, `ai-route-authoring`, `profile-community`, `appearance-studio`, `phone-auth`, `legal-document`, and `admin-moderation`.

It also exposes the 21 component hooks and their state matrix. For every row, verify:

1. `tokens` expresses the global design intent.
2. `CSS` is limited to necessary local differences.
3. `inherited` is an intentional default, not an omission.
4. Default, hover, active, disabled, focus, and error states remain distinguishable.
5. Map controls, sheets, forms, and bottom navigation belong to one visual system.
6. Each of the four brand slots has an independent fixture and clearly reports `Token`, `CSS`, or `default inheritance`.

The live lab is an isolated preview; it does not replace real-route review.

## 8. Package and run real-route review

After visual approval, use one artifact directory:

```powershell
npm run appearance:package -- appearance-work/song-mountain-map appearance-output/song-mountain-map/song-mountain-map.netrin-appearance
npm run appearance:review -- appearance-work/song-mountain-map appearance-output/song-mountain-map
npm run appearance:check -- appearance-output/song-mountain-map/song-mountain-map.netrin-appearance --json
```

`appearance:review` packages again, runs typecheck, the production build, and real browser routes, then generates 20 screenshots: ten screen families in Chinese and English at 390×844.

All eight report checks must be `passed`:

`packageAudit`, `typecheck`, `productionBuild`, `routeSmoke`, `locales`, `viewport390x844`, `reducedMotion`, and `networkIsolation`.

Compare the final package and report hash in PowerShell:

```powershell
$audit = npm --silent run appearance:check -- appearance-output/song-mountain-map/song-mountain-map.netrin-appearance --json | ConvertFrom-Json
$review = Get-Content -LiteralPath appearance-output/song-mountain-map/song-mountain-map.netrin-review.json -Raw | ConvertFrom-Json
if ($audit.packageSha256 -ne $review.packageSha256) { throw 'Package and review hashes do not match.' }
```

Any `failed`, `not-run`, missing screenshot, or hash mismatch means the delivery is incomplete.

## 9. Collaborate with AI through two gates

Invoke the project skill in Codex:

```text
$author-netrin-appearance Create a restrained Song-landscape appearance with muted pine green, paper panels, and restrained motion. The author is … and the license is MIT.
```

The skill stops twice:

1. **After the visual brief:** confirm ID, author metadata, visual language, asset policy, and the safety boundary before any write.
2. **After static validation and live preview:** confirm the preview and intentional inherited areas before packaging or review.

Describe visual feedback directly during iteration:

```text
The panel shadow feels too heavy. Keep the paper hierarchy, reduce the pressure, and rerun JSON check.
```

```text
Compare all ten screen families and align inconsistent borders and focus states across forms, sheets, and navigation.
```

AI remains bound by v3. It must reject scripts, external fonts, remote images, and production deployment while offering the nearest safe token or CSS alternative.

## 10. Delivery checklist and troubleshooting

The pre-submission delivery contains:

```text
appearance-work/song-mountain-map/                       source
appearance-output/song-mountain-map/song-mountain-map.netrin-appearance
appearance-output/song-mountain-map/song-mountain-map.netrin-review.json
appearance-output/song-mountain-map/appearance-zh-CN-*.png
appearance-output/song-mountain-map/appearance-en-*.png
```

Final checklist:

- The v3 package audit is valid and activatable.
- All eight review checks are `passed`.
- All 20 screenshots exist at the correct size and show no obvious visual regression.
- Package and report SHA-256 values match exactly.
- The source contains no script, remote resource, or unlicensed font.
- The development service is stopped and the candidate was never auto-installed.

Common failures:

- `Refusing to overwrite non-empty directory`: choose an empty directory, or edit it directly only after confirming it is the same v3 package ID.
- `unsupported-schema-version`: the input is v1/v2; this workflow does not migrate legacy packages.
- Vite port conflict: use the address actually printed by Vite instead of assuming port 5173.
- `not-run`: inspect the prerequisite failure; later build and screenshot work never masquerades as passed.
- Browser review failure: inspect diagnostics and the matching screenshot before separating an appearance-source problem from an unrelated application build failure.

This tutorial stops at pre-submission delivery. Submission, administrator approval, Function deployment, SSH, migrations, Git commit, and push each require a separate request and authorization.
